# Демобаза dvd_rent

Сценарий показывает установку каталога, чат о схеме, подключение предметного навыка и сверку сгенерированной функции с эталоном. Для установки в свою базу используйте [общую инструкцию](../../README.md).

## Запуск в Docker

Команды рассчитаны на PowerShell и контейнер `postgres1`. Для Debian с PGDG и PostgreSQL 17 установите в контейнер пакет `postgresql-17-http`, если его ещё нет.

Если базы `dvd_rent` ещё нет, восстановите [архив](dvdrental.tar) в новую пустую базу. Команды запускаются из корня репозитория.

```powershell
docker cp .\examples\dvd_rent\dvdrental.tar postgres1:/tmp/dvdrental.tar
docker exec postgres1 sh -c 'createdb -U "${POSTGRES_USER:-postgres}" dvd_rent && pg_restore --exit-on-error --no-owner --no-privileges -U "${POSTGRES_USER:-postgres}" -d dvd_rent /tmp/dvdrental.tar'
```

Установите общий SQL, затем создайте снимок и загрузите навык демобазы.

```powershell
Get-Content -Raw .\sql\install_catalog.sql | docker exec -i postgres1 sh -c 'psql -X -v ON_ERROR_STOP=1 -U "${POSTGRES_USER:-postgres}" -d dvd_rent'
Get-Content -Raw .\examples\dvd_rent\init_dvd_rent.sql | docker exec -i postgres1 sh -c 'psql -X -v ON_ERROR_STOP=1 -U "${POSTGRES_USER:-postgres}" -d dvd_rent'
Get-Content -Raw .\examples\dvd_rent\install_dvd_rent_skills.sql | docker exec -i postgres1 sh -c 'psql -X -v ON_ERROR_STOP=1 -U "${POSTGRES_USER:-postgres}" -d dvd_rent'
```

Демо-скрипт добавляет профиль `default` для `qwen3.8-flash-next` с лимитом ответа в 10 000 токенов на внутреннем endpoint DGX `http://10.8.0.10:8002/v1/chat/completions`. Если профиль с таким именем уже настроен, скрипт использует его. [Пример обзора модели](dvd_rent-synopsis.md)

## Примеры

- [inspect_catalog.sql](inspect_catalog.sql) читает снимок `public`, типы и ограничения таблицы платежей.
- [install_dvd_rent_skills.sql](install_dvd_rent_skills.sql) добавляет `rental-revenue@1` с правилами выручки и привязками к функциям.
- Тот же скрипт привязывает `customer-similarity-cube@1` к `reporting.customer_like`.
  Для этого примера нужны расширение `cube` в схеме `public` и снимок, снятый после установки расширения.
  Навык показывает, как передать пять координат в `public.cube(double precision[])`
  и сравнить две точки через `public.cube_distance`.
- [make_func_customer_revenue.sql](make_func_customer_revenue.sql) создаёт `reporting.customer_revenue`.
- [customer_revenue_baseline.sql](customer_revenue_baseline.sql) возвращает эталонные суммы для двух периодов.

Вопрос про фактическую схему можно задать после создания снимка.

```sql
SELECT answer FROM ai.llm(
    'Ты специалист по PostgreSQL. Отвечай на русском без предисловий.',
    'С какими таблицами связана таблица public.country?'
);

SELECT answer, applied_skills FROM ai.llm(
    'Отвечай кратко по-русски.',
    'Почему фильм повторяется в помесячном отчёте о выручке?',
    p_skills => ARRAY['rental-revenue@1']
);
```

После создания функции её результат можно сверить с эталоном.

```sql
SELECT reporting.customer_revenue(
    1::smallint, timestamp '2007-02-01', timestamp '2007-06-01'
);
```

Для клиента № 1 эталон возвращает 114,70 по 30 платежам в указанном периоде и 0 за период с 1 января по 1 февраля 2008 года. Помесячный отчёт о выручке по фильмам проверяет другой случай: одна и та же пара «название, сумма» может встретиться несколько раз, поэтому при сравнении результата учитывают повторы.

### Похожие клиенты по истории проката

[make_func_customer_like_v4.sql](make_func_customer_like_v4.sql) создаёт
`reporting.customer_like_v4(integer)` коротким русским промптом и показывает результат для
клиента 42. Демо-установщик привязывает `customer-similarity-binary-cube@1` с SQL-шаблоном
и общий навык `postgres-cube@1` из `sql/install_catalog.sql`.

Установите расширение `cube` в схему `public` перед запуском `init_dvd_rent.sql`. Если снимок
уже есть, повторите инициализацию после установки расширения. Пример рассчитан на свободное
имя `reporting.customer_like_v4`. В проверенном запуске Flash Next профиль ревьюера использовал
`compact_review_json_schema = true` и лимит ответа `max_tokens = 10000`.

Шаблон считает квадрат евклидова расстояния по бинарным признакам четырёх множеств
(фильмы, категории, тексты описаний и актёры). Несовпадение города или магазина добавляет
один балл за каждый признак. Для клиента 42 ожидаются 10 разных кандидатов без самого 42.

### Сравнение генерации с документацией PostgreSQL 17

На `dvd_rent` проверили по одному запуску в каждом режиме на Flash Next. Промпты,
профили, полный снапшот и `supabase-postgres-best-practices@1` были одинаковыми.
В тестовой базе для функций была включена одна повторная попытка генерации, а профиль
ревьюера использовал русский язык.
Менялся только `ai.postgres_docs_rag`. Сгенерированные результаты сравнивали с
независимым SQL, а тестовые функции, представления и записи истории откатывали.

| Задача | Без RAG | С RAG |
| --- | --- | --- |
| 10 ближайших клиентов через `cube_distance` | Эталон совпал, 2 попытки, 82,0 с | Ревью прошло, порядок не совпал с эталоном, 1 попытка, 18,1 с |
| Общие фильмы двух клиентов как отсортированный массив | Эталон совпал, 1 попытка, 14,9 с | Эталон совпал, 2 попытки, 88,4 с |
| Представление с помесячной суммой платежей | Эталон совпал, 1 попытка, 31,5 с | Эталон совпал, 1 попытка, 30,2 с |

Для помесячного представления объём входа генератора вырос с 13 015 до 13 744 токенов.
В каждом прогоне с RAG история содержала ссылки переданных выдержек. Время включает
генерацию и ревью, а задачи запускались параллельно. Одной пары на задачу мало
для выводов о качестве и задержке.

Повторный прогон `cube` с сохранением SQL воспроизвёл расхождение. Генератор считал
`DISTINCT rental.inventory_id`, то есть экземпляры, вместо уникальных `inventory.film_id`.
Ревью пропустило различие, а проверка результата обнаружила его.

### Полнотекстовый и гибридный поиск

Те же три задачи запустили на Flash Next по одному разу в режимах `fts` и `hybrid`.
Для обоих режимов использовали один корпус из 180 фрагментов официального PDF,
полный снапшот, компактное ревью и навык Supabase. Конспекты по оптимизации
добавили после сравнения. Тестовые объекты и их записи истории откатили.

| Задача | FTS | Hybrid |
| --- | --- | --- |
| 10 ближайших клиентов через `cube_distance` | Порядок расходится с эталоном, 55,7 с | То же расхождение, 26,5 с |
| Общие фильмы двух клиентов как отсортированный массив | Эталон совпал, 1 попытка, 20,1 с | Эталон совпал, 2 попытки, 78,3 с |
| Представление с помесячной суммой платежей | Эталон совпал, 32,2 с | Эталон совпал, 27,7 с |

В обеих версиях задачи с `cube` SQL считал `DISTINCT rental.inventory_id` вместо
`DISTINCT inventory.film_id`. Компактное ревью пропустило разницу. Режим поиска
и ранги подтверждены по ссылкам в истории. Гибридный режим добавлял к выдаче
в том числе фрагменты о JSON, хотя эти задачи его не использовали.

Три замера отдельного вызова поиска из клиента дали 166–190 мс для FTS и 531–601 мс
для hybrid, включая сетевые задержки. Задачи генерации выполнялись параллельно.

### Наблюдения о схеме

В проверенном снимке было 22 таблицы и представления, 10 функций и агрегатов и 2 пользовательских типа. Обзор Flash Next предложил явно приводить типы для соединения `film_actor.film_id` с `film.film_id`. Обычный `JOIN` без приведения вернул 5 462 строки. В таблице `payment` колонка `rental_id` одновременно имеет `NOT NULL` и внешний ключ с `ON DELETE SET NULL`. Генератору важно учитывать оба свойства.
